# Building My First Management Apps

**August 17, 2026**

I'm starting to run into a problem with the RitesDev website.

I have a blog, and every time I want to create or change a post, I have to work directly with the files. That's not really a huge problem while I'm building everything, but I don't want to have to edit the website's code every time I want to write a blog post.

So I decided to make something to manage it.

## My first management app

I'm building a small blog management app specifically for the RitesDev blog.

The idea is pretty simple: instead of opening the blog files and editing everything manually, I can open an app, use buttons and form inputs, and manage the posts from there.

Right now it can create, edit, and delete blog posts through the UI.

Since I'm running Fedora, I can make a `.desktop` file that points directly to my Node script. That means I can launch the manager like a normal application on my computer without having to build or compile it every time I make a change.

This is already making managing the blog much easier.

Then I had another thought.

If I can make an app to manage the blog, why can't I make another one to manage the rest of the website?

## A second management app

So I'm making another app for the site's content.

This one is separate from the blog manager. Instead of managing blog posts, it is designed to display and edit information used throughout the main website, such as page text and contact information.

It works on the same basic idea as the blog manager: I have a UI where I can view and change the information instead of having to dig through the website's source code.

It's much less finished than the blog manager, though.

The rendering is still pretty glitchy, and I'm continuing to work out how I want the app to handle everything.

Both applications are currently separate, but they're part of the RitesDev setup and run locally on my computer alongside the website.

## The funny part

I started the blog manager because I wanted to make managing the website easier.

Now I have two separate applications to manage.

So I've technically solved the problem...

...and created another one.

In all seriousness, though, I'm pretty happy with how this is turning out. The blog manager is already useful, and I think the site content manager will become just as useful once I get the bugs worked out.

I'm going to keep improving both of them as I continue building RitesDev and the blog.
