# Putting the Websites in One Workspace

At first, I have the RitesDev website and blog as separate projects. This is a reasonable way to get started, but it means I track the same overall effort in more than one place.

I bring the work into a shared environment and organize the supporting development apps alongside it.

## The project grows beyond one site

I have the public business website, the blog, and the local tools I make to manage content. They serve different purposes, but they connect to the same RitesDev project.

Having the work together makes it easier to see those connections. It also gives me a place to think about which information and tools should be shared.

## A workspace is a starting point

Moving projects together doesn't automatically make the architecture perfect. I still decide how to organize each site and how tools interact with it.

But a shared home for the work feels like a useful step. RitesDev is more than a single website, and I want the code to reflect that.
