# Putting the Websites in One Workspace

For a while, the RitesDev website and the blog were separate projects. That was a reasonable way to get started, but it also meant I had to keep track of the same overall effort in more than one place.

I started bringing the work into a shared environment and organizing the supporting development apps alongside it.

## The project was getting bigger than one site

There was the public business website, the blog, and the local tools I was making to manage content. They all served different purposes, but they were connected to the same RitesDev project.

Having the work together makes it easier to see those connections. It also gives me a place to think about which information and tools should be shared.

## A workspace is a starting point

Moving projects together doesn't automatically make the architecture perfect. I still have to decide how each site should be organized and how tools should interact with it.

But having a shared home for the work feels like a useful step. RitesDev is turning into more than a single website, and I want the code to reflect that.
